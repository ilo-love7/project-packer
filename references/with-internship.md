# 有实习经历怎么写

这个 skill 是从 `internship-packer` 转型来的，转型之后一直在解决"没有实习怎么办"，反而把"有实习怎么写"这件事丢了。这份文档补回来。

**先说结论**：有实习是优势，但它带来一类新的风险——**在职项目的证据更强，验证也更容易**。个人项目吹过头，面试官只能靠追问；实习吹过头，背调一个电话就能核实。所以这一类的纪律不是"写得更狠"，是"写得更准"。

---

## 一、在职项目 vs 个人项目：措辞的四条差异

| 维度 | 个人 / 课程项目 | 在职项目 |
|---|---|---|
| 归属 | 需要主动说明"3 人小组里我负责哪块" | 默认是团队成果，**必须主动划清自己那块**，否则一追问就含糊 |
| 结果 | 自测指标，要写口径（本机压测、种子数据） | 生产指标，可以写"线上""真实用户"，但要能说清是哪个环境、哪个时间段 |
| 影响面 | 通常只影响自己 | 可以写"被 N 个下游服务依赖""支撑日活 X"，**前提是你能说清这个数字怎么来的** |
| 协作 | 同学、组员 | 可以写"与 PM / 算法 / 运维协作"，这是实习独有的信号，别浪费 |

**最常被浪费的一条是第四行**。个人项目写不出"和产品经理对齐需求、和运维一起做灰度"，这是实习最能体现"能在真实组织里工作"的地方。但别写成"负责跨部门沟通"——要写成具体的一次协作：`与 PM 对齐 3 版需求文档，把首版 17 个需求砍到 6 个`。

---

## 二、公司名写不写

**写。** 不写公司名等于放弃实习最大的价值，而且背调查得到。

三种例外：

| 情况 | 怎么写 | 说明 |
|---|---|---|
| 公司知名度低，名字看不出行业 | 公司名 + 一句行业定位：`XX 科技（跨境电商 SaaS，B 轮）` | 别指望面试官去搜 |
| 涉密 / 军工 / 金融核心系统 | 写行业与规模，不写具体系统名：`某股份制银行 · 核心账务系统` | 公司名可以写，系统名不行 |
| 竞品公司（投对手时） | 照写。回避反而显得心虚 | 但别在面试里评价前东家的业务策略 |

**外包 / 驻场**要写清：`XX 人力（驻场 YY 银行）`。不写清楚，背调时"你到底是谁的员工"会变成一个尴尬问题。

## 三、NDA 边界：能说什么，不能说什么

实习经历最容易踩的不是夸大，是**泄密**。四条界线：

1. **能说方法，不能说实现细节**。"用分库分表解决了单表过亿的写入瓶颈"可以；"按 user_id 取模分 64 库、每库 16 表"不行——那是内部架构。
2. **能说量级，不能说精确业务数字**。"日订单百万级"可以；"2025 年 Q3 日均订单 137 万"不行，除非是公开财报数字。
3. **能说自己的产出，不能说他人未公开的工作**。"我负责的模块把接口耗时从 800ms 降到 120ms"可以；"我们组把整个中台重写了"不行，那不是你做的，也可能是未公开的。
4. **能说技术选型的理由，不能说未公开的业务策略**。"选 Kafka 是因为需要削峰"可以；"公司明年要切到 XX 业务线"不行。

被问"这个能细说吗"时的标准答法：

```text
"具体实现涉及内部架构，我不方便展开。能说的是方法和结果：
我用 X 思路解决了 Y 问题，把 Z 指标从 A 降到了 B。如果您想聊技术细节，
我可以讲讲当时的取舍——为什么没选另一个方案。"
```

这个答法同时做到了三件事：不泄密、不显得心虚、把话题引回自己擅长的地方。

## 四、实习经历的四个必问题

这四个问题在实习面试里的出现率远高于项目经历，必须提前备好。

### 1. "这个项目里你具体负责哪部分？"

最危险的答法是大包大揽（"基本都是我做的"）和过度谦虚（"我就打了个杂"）。正确结构是**三层**：

```text
"整个链路是 A → B → C。A 是我独立做的；B 是我和另一个后端一起做的，
我负责接口设计和压测，他负责数据同步；C 是运维做的，我只提了需求。
上线后我盯了两周监控，主要看 P99 和错误率。"
```

### 2. "团队多少人？你向谁汇报？"

这个问题在验证你是不是真的待过。答不出汇报关系，基本就露了。如实答：`后端 4 人，向技术负责人汇报，双周向业务方同步一次`。

### 3. "上线了吗？效果怎么样？"

**没上线就直说没上线**，然后说清楚停在哪个环节、为什么。这比编一个"上线了效果很好"安全得多——上线的东西背调一问就知道。

真没上线时的说法：

```text
"做到联调阶段，因为 XX 原因没有推到生产。但压测和代码评审都过了，
我这边留下了完整的压测基线和接口文档。"
```

### 4. "为什么离职 / 为什么没留用？"

不卖惨、不甩锅、不评价前东家。三段式：

```text
"实习期是 3 个月，到期时团队 HC 冻结了。带我的师兄给我写了推荐语，
我也把交接文档做完了。这段经历让我确定想做后端，所以现在在找正式的机会。"
```

`HC 冻结` / `业务调整` / `实习期满` 都是中性且常见的原因，不需要修饰。

## 五、实习和项目怎么排

有实习时，版面顺序变了：

```
教育背景
实习经历          ← 提到项目之前，这是最强的证据
项目经历          ← 保留 1-2 段，不要全砍
技能 / 奖项
```

三条规则：

1. **实习放项目前面**。工作经历按时间倒序、项目按相关度倒序这条规则（见 `references/multi-project.md` 第四节）在有实习时依然成立——只是实习整体排在项目整体之前。
2. **项目不要全砍**。有实习的人常犯的错是只留实习，结果简历只有一段经历，反而显得单薄。留 1-2 段最能体现技术深度或广度的。
3. **实习只有一段时，把它写足**。一段实习可以写 4-6 条（L1 档位），因为它经得起追问。

## 六、两种实习的写法差异

### 大厂螺丝钉：写"深度"和"协作面"

在大厂你只负责一个模块的一小块，硬写"负责整个系统"一追问就崩。正确打法是**把一个点挖到底**：

```text
· 负责订单导出模块（日调用 40 万次），把单次导出耗时从 12s 压到 1.8s：
  定位到 N+1 与全量加载，改为游标分批 + 字段裁剪；
· 与 PM 对齐 3 版需求，砍掉 2 个低频场景，把首版工期从 6 周压到 4 周；
· 模块上线后接入 3 个下游服务，写了交接文档与 12 个回归用例。
```

**关键是把"小"讲成"深"**，而不是把小讲成大。面试官对大厂实习的预期本来就是"你只做一小块"，你越诚实，他越信你其他部分。

### 小厂全栈：写"广度"和"闭环"

小厂实习往往什么都干，但容易写成流水账。正确打法是**按闭环组织**，不是按任务列表：

```text
· 独立负责会员系统从 0 到 1：需求梳理 → 表设计 → 接口 → 前端页面 → 上线监控；
· 上线 3 个月累计服务 1.2 万注册用户，把注册转化率从 41% 提到 58%
  （埋点数据，对比改版前后各 2 周）；
· 兼任部分运维：把部署从手动 FTP 改为 GitHub Actions 自动发布，发布耗时从 20 分钟降到 3 分钟。
```

**关键是别写成"我还做了 A、还做了 B"**，要写成"我一个人把一件事做完了"。广度本身不是优势，**闭环**才是。

## 七、实习太短（< 3 个月）怎么办

短实习不是硬伤，**解释不清才是**。两种处理：

- **有产出**：照常写，时间如实。3 个月做出东西比 6 个月打杂更有说服力。
- **没产出**：降为 L2（2-3 条），重点写"看到了什么"而不是"做成了什么"：

```text
· 参与 XX 系统的日常迭代，独立完成 4 个接口的改造与联调；
· 熟悉了团队的 code review 流程与灰度发布机制。
```

第二条看着弱，但它诚实且不可被证伪。**别为了撑长度编一个"主导了 XX 项目"**——3 个月的实习生主导项目，面试官第一反应就是不信。

## 八、反模式

| 反模式 | 为什么错 | 改法 |
|---|---|---|
| 把实习写成"某互联网公司"不写名字 | 放弃最大价值，且背调查得到 | 写公司名 + 行业定位 |
| 团队成果全说成自己的 | 背调一个电话就穿，且是诚信问题 | 三层结构划清自己那块 |
| 没上线说成上线了 | 上线与否极易核实 | 如实说停在哪个环节 |
| 写内部架构细节来证明深度 | 泄密，且显得不专业 | 说方法与取舍，不说实现 |
| 有实习就把项目全砍 | 只剩一段经历，反而单薄 | 留 1-2 段项目 |
| 短实习硬撑成"主导" | 3 个月主导项目，第一反应是不信 | 降 L2，写"看到了什么" |
| 离职原因写"团队氛围不好" | 评价前东家是减分项 | 用中性原因：HC 冻结 / 实习期满 |

## 九、自检清单

- [ ] 公司名写了，且有一句行业定位（知名度低时）
- [ ] 每条能说清"我负责的那部分"边界，不含糊也不包揽
- [ ] 没有内部架构细节、未公开业务数字、他人未公开的工作
- [ ] 上线与否如实，没上线写清了停在哪个环节
- [ ] 汇报关系、团队规模能答出来
- [ ] 离职原因中性，没有评价前东家
- [ ] 实习排在项目之前，但项目没有全砍
- [ ] 数字都能在 `facts.md` 里找到证据指针（跑 `check_facts.py`）
- [ ] 交付前跑过 `scripts/scan_privacy.py`——实习稿最容易残留内网地址、内部系统名、同事联系方式
