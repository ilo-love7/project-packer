# 持久资产规范：事实档案 + 真题库

这两个文件是 skill 的长期记忆，存在用户工作区（默认根目录，可指定）。它们让每次包装不再是"从零开始"，也让"数字一致"从纪律变成机制。

## 一、事实档案 facts.md

**唯一事实源。** 每个项目一节，任何包装输出与此冲突时停下核对。

```markdown
# 事实档案（最后更新：YYYY-MM-DD）

## [项目名]
- 时间：YYYY.MM - YYYY.MM
- 载体：（课程项目 / 科研实践 / 竞赛 / 学生工作 / 开源）
- 角色：（独立 / 主导 / 参与执行 + 一句定位）
- 一句事实：
- 数字清单：
  | 数字 | 口径 | 证据指针 | 取证方式 | 防守分 |
  |---|---|---|---|---|
  | 5.9% | 官方划分中位误差 | results/xx.csv | 读该文件第 N 列中位数 | 3 |
- 已批准措辞：
  - 标准档：（定稿条目原文）
  - 强化档：（定稿条目原文，逐条对应防守预案指针）
- 追问树状态：3 层 ×N 问，最后更新 YYYY-MM-DD
- 边界卡摘要：
```

### 规则

1. **入档先于包装**：新素材（数字、产出、影响）必须先入档（含证据指针）才能出现在交付物里。用户口述的新数字 → 先问来源，入档后才可用。
2. **输出前 diff**：交付稿中每个数字、日期、口径与档案逐项比对，不一致 → 停下问用户"以哪个为准"，**不允许两个版本并存**。核对后更新档案的"最后更新"。
3. **措辞档位记录在案**：档案存两档定稿原文。下次包装同一段经历直接取用，不再凭记忆重写。
4. **防守分随档更新**：追问树扩了、证据补了，分数可以涨；发现证据失效（文件删了、口径变了）必须降分并提示用户。
5. **隐私同样适用**：档案里不放密钥和他人敏感信息。

## 二、真题库 question-bank.md

复盘回写的沉淀池，按公司/轮次/类型归类。

```markdown
# 真题库

## [公司/场景] · [轮次] · YYYY-MM-DD
- 被问到：（面试官原话，尽量逐字）
- 类型：（技术深挖 / 归属质疑 / 载体质疑 / 压力题 / 反常识题）
- 结果：预判命中 ✅ / 树里没有但答上了 🟡 / 答崩了 ❌
- 处理：已回写追问树第 N 层 / 已补边界卡 / 待补证据
```

### 规则

1. 复盘回写（SKILL.md 阶段 6）时同步入题库，一条真实问题 = 一条记录。
2. **命中率 = 追问树预判命中数 / 真实问题总数**。每次复盘后统计；命中率 < 50% → 下次包装时扩大追问树覆盖（每条 bullet 至少 2 层预判，并做树外红队推演）。
3. 题库跨项目共享：同一公司再面、同类岗位再投时，直接调出历史真题先练。
4. ❌ 项是最高优先级素材：下次陪练模式优先考这些。
