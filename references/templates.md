# 输出模板

## 1. 简历条目（XYZ 公式）

```text
[项目名（载体定性：个人项目 / 校级竞赛 / 科研助理 / 开源贡献 / 学生工作）· 一句定位]   [时间]
· [动词] [成果 X]，[一个方法/工具短语 Y]，[量化结果 Z，带证据]；
· [动词] [解决的关键问题 + 前后对比数字]，[一句话归因]，[留下的可验证产出]；
· [动词] [超出复现/本职的扩展成果]，[量化结论/影响]。
```

规则：每条 ≤2 行；数字进 bullet；括号给上下文（数据规模、划分口径）；末条可放工程化亮点（测试、CI、文档）；标题行写清载体性质，不冒充实习。

**过程细节下沉（最高优先级的措辞规则）**：读者视角下优秀简历只讲三件事——做了什么、用什么做、结果是什么。一条 bullet 只装**一个动作**：
- "怎么发现的 / 排除了哪些假设 / 修复细节 / 机制怎么搭建"这类过程，全部下沉到追问预判树和 STAR 故事，**不上简历**；
- 方法词只留一个最有信号量的（如 "bootstrap 95% CI"、"Kaplan-Meier"），两个以上就挑一个；
- 自检法：把 bullet 读一遍，出现两个以上动作串联（发现→修复→建立…）→ 拆成两条或砍掉过程只留结果；
- 判断标准不是"这个细节厉害吗"，而是"面试官不问、这个细节有没有人看"——没人看就下沉。

**工具链显性**：工具/软件名必须出现在 bullet 里（Python、pandas、SolidWorks、Origin、AutoCAD…）——这是 ATS 关键词的直接来源，也是可信度信号。每条至少 1 个；方法名（如 Kaplan-Meier、bootstrap）与工具名二选一时优先工具名，方法名只在有信号量时保留一个。
**成果大白话**：量化结果要让外行看懂——术语后跟白话解释（括号内），或白话为主、术语做锚。检验法：读给非本专业朋友，5 秒内能复述"这人做了什么、结果多好"才算过。
白话化红线：**不能歪曲口径**——中位数不能说成平均数，"仅保量级"不能说成精确值，相对倍数要说明基准。技术钩子（一个术语）允许保留，全白话到丢掉可信度同样不合格。

## 2. STAR 深挖故事

```text
【S 情境】项目背景与我的角色（2 句）
【T 任务】要解决什么，为什么难（1-2 句）
【A 行动】分步：发现信号 → 排除假设 → 定位根因 → 修复/验证（含工具与判据）
【R 结果】量化前后对比 + 留下的机制（防回归断言/文档/测试）
【追问预判树】
  第 1 层（几乎必问）：为什么 X？→ 答案要点 + 证据指针
  第 2 层（技术深挖）：Y 的原理 / 如果数据是 Z 怎么办？→ 答案要点 + 证据指针
  第 3 层（压力/归属）：这是你自己做的吗？→ 分层讲法：哪些我独立完成、
    哪些工具辅助、我怎么验证（用证据说话，不闪躲）
```

无硬数字经历的 STAR 变体：A 侧重【冲突/权衡 → 决策依据 → 事后验证】，R 用替代量化 + 留下的机制（制度、模板、复盘文档）。

## 3. 电梯稿（30 秒）

```text
我是[身份]，[一句话项目定位]。我[核心动作]，[量化结果]，
这个经验能直接迁移到贵司的[岗位具体场景]。
```

外企/英文 JD 场景输出中英双版；英文版控制在 60 词内。

## 4. JD 证据映射表

| JD 关键词/要求 | 我的证据（含文件/截图指针） | 强度（强/中/弱） | 用在哪（主条目/技能行/只备面试） |
|---|---|---|---|

## 5. 按岗位换弹头

同一个项目对研发/测试/数据/工艺岗强调点不同。先问目标岗位，再决定每条 bullet 的重心：

| 岗位类型 | 强调什么 |
|---|---|
| 研发/算法 | 方法选型依据、量化对比、统计口径 |
| 测试/质量 | 数据审计、防回归断言、交叉验证（复测思维） |
| 工程/平台 | 管线自动化、缓存、可复现性、CI |
| 分析/咨询 | 归因链条、结论的诚实边界、可视化 |

## 6. 诚实边界卡

```text
- [不能说满的点]：[为什么] → [被追问时的句式：给事实 + 限定词，不夸大不自贬]
```

示例句式："点估计接近，统计差异未定" / "贡献是实验归因，不是理论证明" / "由 AI 辅助生成、由我逐条验证后采信"。

## 7. 替代量化（无硬数字时用）

没有可复算指标 ≠ 没有量化。按五类替代维度找数，全部必须问用户要来源，不得估算冒充实测：

| 维度 | 问法 | 示例 |
|---|---|---|
| 规模 | 覆盖多少人/多少件/多少页 | 组织 174 人英语打卡活动 |
| 频次 | 多久一次、坚持了多少期 | 连续 12 周每周复盘 |
| 时长/工期 | 从启动到交付多快，比预期快多少 | 两周内完成原定一个月的流程搭建 |
| 对比基线 | 接手前 vs 交接后 | 打卡完成率从 40% 升到 78%（需有记录） |
| 产出物 | 留下了什么可数的东西 | 3 份 SOP 文档、1 套活动模板被下一届沿用 |

注意：替代量化强度低于实测指标，措辞上少用百分比、多用规模词；拿不到记录的对比基线宁可不写。

## 8. 载体重定位话术

包装经历的最大攻击面不是技术追问，而是身份质疑："这段是实习吗？""为什么你还没有实习经历？"。提前备好，核心打法是**主动翻译，不被动辩解**：

```text
【被问"这是实习吗"】
不装是，也不贬低是："这是我在没有实习机会的情况下，自己按公司级标准做的
完整项目——从[起点]到[交付]，我把它当成实习来要求自己：[举一个自证的细节，
如断言防回归/复盘文档/真实数据审计]。"

【被问"为什么没有实习经历"】
三段式：客观原因一句带过（地域/课业/信息差，不卖惨）→ 我做了什么补位
（项目/竞赛/学生工作的闭环）→ 收尾指向岗位："所以我现在缺的不是投入度，
是一个把这套打法放到真实业务里的机会，这也是我来面这个岗位的原因。"

【禁止】把课程项目说成公司实习；编造"内推未果""家里有事"等假原因；
过度自贬"我确实什么都没做过"。
```

载体定性在简历标题行已经诚实标注，面试话术与简历口径必须一致——话术是给"诚实标注"配的进攻性解释，不是给"含糊标注"配的遮羞布。

## 9. 包装强度分级（标准档 / 强化档）

核心规则一句话：**夸大的天花板 = 追问三层的防守能力。** 措辞可以拉满到事实允许的强度，事实（数字、时间、署名、规模、隶属）一个不能动。

| 维度 | 标准档 | 强化档 | 两条档位的红线 |
|---|---|---|---|
| 动词 | 如实动词（复现、实现、参与执行） | 事实允许的最强动词（主导、独立完成、从零搭建——仅当事实真撑得起） | 复现写自研、参与写主导 = 越界，cut |
| 定位 | 按真实性质命名（课程项目、个人项目） | 抬定位不换事实：课程项目→"完整闭环项目"，写明"按工程标准交付（测试/文档/断言）" | 冒充公司/实验室隶属 = 越界，cut |
| 影响面 | 写直接产出 | 补全影响链："被下一届沿用""纳入实验室例会材料"（须真实） | 编造影响 = 越界，cut |
| 数字 | 原样 | 原样，一个不动 | 48 片写 500 片 = 定时炸弹，cut |
| 防守 | 常规追问树 | **每条强化 bullet 必须在追问树中有逐条防守预案**（这个动词为什么撑得起、证据在哪） | 无防守预案的强化表述 = 自动降级回标准档 |

用法：
- 海投 / 简历初稿 → 标准档（稳）；
- 面试临近 / 定向投递 → 强化档（每条都有防守预案再上）；
- 同一段经历可以对不同岗位用不同档位，但**同一份材料里口径必须统一**，且两档的数字完全一致——面试官拿两版简历对比时，数字对不上比措辞弱更致命。

## 10. 防守分评分卡

每条 bullet 打 0~3 分，交付包必须附评分卡：

```text
| bullet（前 15 字） | 证据分 | 树覆盖分 | 防守分 | 判定 |
|---|---|---|---|---|
```

- **证据分（0-2）**：有可复算证据 + 取证方式 = 2；有指针但未实际验证 = 1；仅口述 = 0；
- **树覆盖分（0-1）**：该条在追问预判树中有对应预案 = 1；无 = 0；
- **判定**：3 = 敢投任何公司；2 = 可投，面试前补追问预案；1 = 降档重写；0 = 删或改定性表述。

规则：
- 防守分 < 2 的条目**禁入强化档**（与 templates 第 9 节「包装强度分级」联动）；
- 全篇平均分 < 2 → 触发"最小补证据方案"：列出哪几条补什么文件/截图能涨到 2；
- 评分卡同步回写事实档案（每条数字的防守分列）。

## 11. ATS 机筛适配（可选交付）

机筛过不了，追问树写得再好都没人看。英文/大厂 JD 必做，中文中小公司可选。

**纯文本版规范**：
- 去表格、去特殊符号（·、★、│），bullet 统一用 "- "；
- 日期统一 YYYY.MM（不混用"2024年9月""2024.09""24.9"）；
- 每条 bullet 单行不硬换行（交给 ATS 自己折行）；
- 技能词用 JD 原文拼写（JD 写 PostgreSQL 就不写 PG）。

**关键词覆盖流程**：
1. 从 JD 提取硬技能/工具/方法名词表；
2. 对照交付稿逐词检查命中，输出覆盖率（命中数/总数）；
3. 缺词三分类：**真缺**（给最小补做方案）/ **有而不叫这名**（诚实换词，如"灰度对比"→"A/B 测试"，前提是事实确实是同一件事）/ **写不出**（放弃，不堆砌）。

**反模式**：不堆砌关键词、不搞白字隐写（把关键词藏在空白处）——人眼一眼识破且 ATS 反作弊会标记。覆盖率的诚实下限：缺就缺，用"补做 X"换，不用假词凑。
