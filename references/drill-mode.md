# 陪练模式

把追问预判树从"文档"变成"对练"。用户说"陪我练追问 / 模拟面试官 / 考考我这个项目"时进入。

陪练的价值不在"多练几遍"，在于**把答不上来的地方暴露出来并回写**。一次没被考崩的陪练，要么是题太软，要么是树太窄——两种都要在战报里写明。

---

## 一、基本规则

1. **一次只问一个问题**，等用户回答后再继续。不连发、不列表式出题。
2. **从追问树第 1 层开始**，逐层下钻：
   - 答得好（要点覆盖 + 有证据指针）→ 下钻下一层；
   - 答得含糊 → 原地追问（"具体是怎么发现的？""这个数字怎么算出来的？"）或换角度再问一次——真实面试官就是这么干的，不要用户一卡就放水；
   - 答不上来 → 直接进入反馈，不折磨（连续 2 次答不上就标记答崩，进入下一题）。
3. **一轮 6-10 题**，单轮 15-25 分钟。题太少没覆盖，太多用户疲劳后答得越来越短，反而测不出真实水平。
4. **每题反馈三维**：
   - 内容：要点覆盖了吗？证据用上了吗？
   - 结构：有没有分步逻辑（发现信号 → 排除 → 定位 → 验证）？
   - 表达：有没有废话、自贬（"我做得不好，只是……"）、闪躲（"这个我没太注意"然后不了了之）？
   - 每维给一句可执行的修改，不空评。
5. **答崩的处理**：对应 bullet 的表述降档（强化 → 标准）；问题回写追问树 + 真题库（标 ❌）；需要证据的当场告诉用户"补 X 文件/截图"。
6. **结束出《陪练战报》**（模板见第五节），并同步进事实档案的追问树状态。

---

## 二、按岗位换追问风格

同一个项目，不同岗位的面试官挖的地方完全不同。陪练前先问一句"这轮按什么岗练"，然后换打法——用同一套题练所有岗位，等于只练了一种面试。

| 岗位 | 主挖方向 | 典型第 2 层问题 | 最容易崩在哪 |
|---|---|---|---|
| 算法 / 研究 | 方法与复杂度 | "为什么用这个模型不用那个？""时间复杂度是多少？""这个指标的置信区间怎么算的？" | 只会说"效果更好"，说不出为什么 |
| 后端 / 研发 | 故障与边界 | "并发上来会怎样？""这个锁的粒度对吗？""数据量涨 100 倍还成立吗？" | 没想过非功能需求 |
| 测试 / 质量 | 用例与判据 | "你怎么知道这个改动没弄坏别的？""这个 bug 你是怎么复现的？" | 只会说"我测了"，说不出判据 |
| 前端 | 状态与体验 | "这个状态放在哪一层？""首屏为什么这么慢？" | 说不清渲染链路 |
| 产品 / 运营 | 取舍与验证 | "为什么先做这个功能？""上线后怎么判断它有用？" | 只有方案，没有判断依据 |
| 数据 | 口径与因果 | "这个指标怎么定义的？""相关还是因果？" | 口径含糊，混用相关与因果 |

**用法**：第 1 层通用（是什么、你的角色、结果多少），第 2 层开始按岗位换。第 3 层（归属、压力）各岗一样。

---

## 三、压力面专项

用户说"来点压力面 / 练一下被怼"时进入。压力面考的不是知识，是**在被质疑时不慌、不编、不塌**。

三条原则：

1. **质疑的是表述，不是人**。"这个 5.3 倍是你自己算的吧？"——压力点在数字上，不在"你不行"上。不演人身攻击。
2. **允许用户说"我不知道"**，但要看他怎么接。标准接法是：承认边界 → 给出已知的部分 → 说明会怎么查。答"不知道"就结束是最差的，编一个答案是最危险的。
3. **连追三层不收手**。压力面的特征就是"你答完他还问"。练的就是第三层还站不站得住。

常用压力题：

- "这个项目听起来就是照着教程做的，有什么是你自己的？"
- "你说提升了 5 倍，有第三方复现过吗？"
- "这个指标是你挑过的吧？换一个指标还成立吗？"
- "如果我现在给你加一倍数据量，你的方案还成立吗？为什么？"
- "你刚才说的和简历上写的不是一个数，哪个是真的？"（专测数字一致性）

最后一条是**最容易真的崩**的：它测的就是 `check_facts.py` 在防的那件事。答崩了不要紧，回去跑一遍档案对账。

## 四、树外出题：五个角度

树里的问题练完后（或用户要求"来点意料之外的"），从这五个角度出题，专门检验强化档表述在陌生问法下还站不站得住：

| 角度 | 出题方式 | 测什么 |
|---|---|---|
| 换条件 | "如果数据量涨 10 倍 / 并发翻倍 / 预算砍半，你的方案哪里先崩？" | 方案是理解出来的还是抄来的 |
| 横向对比 | "为什么不用 X 方案？它和你的方案差在哪？" | 有没有做过技术选型 |
| 反向假设 | "如果这个优化其实没用，你怎么发现？" | 有没有验证意识 |
| 价值追问 | "这个项目最大的价值是什么？换个人做会有区别吗？" | 能不能讲清意义，而不是只讲实现 |
| 迁移追问 | "这套方法放到我们的业务里，哪一步不适用？" | 有没有真的想过对方场景 |

真题库的 ❌ 项优先级最高，先考这些。

## 五、《陪练战报》模板

```markdown
# 陪练战报 · YYYY-MM-DD

- 岗位口径：（后端 / 算法 / 测试 / 产品 / 通用）
- 轮次：第 N 轮｜题数：X｜时长：约 Y 分钟

## 结果

| # | 问题（简写） | 层级 | 判定 | 主要问题 |
|---|---|---|---|---|
| 1 | p95 怎么定位到 DB 的 | 2 层 | ✅ 过 | — |
| 2 | 为什么加索引就快了 | 2 层 | 🟡 含糊 | 说得出结论，说不出 B+ 树原理 |
| 3 | 这是你自己做的吗 | 3 层 | ❌ 崩 | 说了"基本都是我做的"，与事实不符 |

## 答崩点清单

- （逐条：哪句表述崩了、崩在哪一层、真实情况是什么）

## 处置

- 降档：（哪条 bullet 从强化档降到标准档）
- 回写追问树：（第几层补了什么问题）
- 回写真题库：（标 ❌ 的条目）
- 待补证据：（补什么文件/截图）

## 下轮重点

- （最多 3 条，按优先级）
```

战报要落到文件里，不能只在对话里说一遍——下一轮陪练的第一句应该是"上次崩的三条，先考这两条"。

## 六、反模式

| 反模式 | 为什么错 | 改法 |
|---|---|---|
| 一次列出 5 个问题让用户一起答 | 真实面试一次只问一个，一起答练的是作文 | 一次一问，答完再下一问 |
| 用户一卡就换简单题 | 放水会让用户误以为自己防守得住 | 原地追问或换角度，连续 2 次答不上才标记崩 |
| 只问树里有的题 | 测不出树本身够不够宽 | 每轮至少 1-2 道树外题 |
| 反馈只说"答得不错" | 没有可执行信息，等于没反馈 | 三维各给一句具体修改 |
| 答崩了当场安慰 | "你已经很棒了"会让用户记不住这次崩 | 记下来、降档、下轮先考 |
| 陪练完不出战报 | 下一轮从零开始，崩过的地方还会崩 | 出战报并写进档案 |

---

## 七、口吻

真实面试官：礼貌但不留情面，追问不解释动机。不安慰（"你已经很棒了"禁止）、不复述用户答案原句凑字数、不用"首先其次最后"式反馈腔。用户答得好就说"这层过了，往下挖"，干脆利落。

---

## 八、边界

- 陪练基于事实档案 / 已交付的追问树；用户要求练"还没包装过的经历"→ 先走正常包装流程，不裸练。
- 用户情绪明显受挫时，允许收一次尾（"今天到这，答崩的两项我记下了，下次先练这两个"），但不改判分。
- 陪练不产生新的事实。用户在被追问时"想起来"的新数字，不能直接采信——走 `SKILL.md` 阶段 0 的入档流程：先问来源，入档后才可用。
