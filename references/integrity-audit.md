# 对抗审计检查单

交稿前按五个视角逐条过，每条给结论：pass / fix（附改法）/ cut（附理由）。存在未处理 fail 项不得交付。

## 视角 A：背调审核员（事实层）

1. 雇主/载体名称真实存在且与用户经历一致？（无实习载体时是否误写成"实习"？）
2. 时间线与总时间轴一致，无重叠或矛盾？
3. 角色/头衔与实际贡献匹配，无拔高？
4. 团队成果/他人贡献未被据为己有？
5. 每个 bullet 至少能指出一个证据（文件/截图/可复算）？
6. 证书、奖项、成绩有据可查？
7. **载体一致性**：简历标题行的载体定性、面试话术（载体重定位）、电梯稿三处口径一致？没有"简历写个人项目、面试却说实习"的漂移？
8. **替代量化的来源**：规模/频次/对比基线类数字均有用户确认的来源，无估算冒充实测？

## 视角 B：技术面试官（内容层）

9. 每个数字可复算？口径已说明（中位/均值、划分方式、n 多少）？
10. 对比性数字（如"优于论文/基线"）有同口径依据？没有就改成限定句式？
11. "优化/提升"给了前后对比数字？
12. 方法名/统计概念用对（不张冠李戴）？
13. 追问预判树覆盖了简历里最薄弱的声明？
14. 准备了"为什么不用更热门的 X 方法"？
15. 准备了"这是你自己做的吗"的分层答案（AI 辅助披露口径）？
16. **强化档防守预案**：采用强化档时，每条强化 bullet 在追问树中有逐条防守预案？无预案 → fix（补预案）或降级回标准档；两档数字完全一致？

## 视角 C：措辞红绿灯

| 级别 | 措辞 | 规则 |
|---|---|---|
| 绿（可直接写） | 复现到 [量化结果]（有数据）；独立实现；诊断出并修复；设计了对照实验 | 附证据即可 |
| 黄（必须带限定词） | 优化（附前后数字）；主导（限真实主导）；提出（限真原创，能答"与已有工作的区别"）；自动化（说明程度） | 缺限定词 = fix |
| 红（禁止） | 虚构雇主/头衔；复现→自主研发；课程项目→公司实习；AI 产出说成全部亲手且拒绝披露；夸大样本量/指标口径；无同口径依据说"统计显著优于"；编造补位原因（假内推/假家事） | 必须 cut |

### 黄档的可执行版本（R7）

上表黄档原本只是一句话要求，判断全凭 agent 手感。`scripts/lint_resume.py` 的 R7 把它拆成
三类词 + 三种限定物——每类词缺的是不同的东西，不能用一套判据糊过去：

| 类别 | 词 | 缺了会怎样 | 判定用的标记 |
|---|---|---|---|
| 效果词 | 优化 / 提升 / 降低 / 缩短 / 减少 / 加速 / 改善 / 提高 | 「优化了加载流程」——优化到哪儿去了？ | `→` `->` `=>`；`从 N`；`降至 N` / `提升至 N`；任意 `%` |
| 归属词 | 主导 / 牵头 / 独立完成 / 全权 | 「主导平台建设」——主导了多大盘子？ | 数字 + 人/名/位/个/条/项/步/类/家/模块/服务/接口/页面/系统；或 团队/小组/跨部门/跨团队/全流程/多人 |
| 程度词 | 自动化 | 「实现了流程自动化」——自动化到哪一步？ | 百分比；定时/每日/每周/每天/每月/自动触发/全量/全部/端到端 |

三条设计取舍，值得知道，因为直接决定了你该怎么读它的告警：

- **只给 WARN，绝不给 ERROR。** 黄灯词本身不违规，违规的是「不带限定词就用」，
  而「有没有限定词」是词法判断。R2 的红灯词可以判死（自主研发这四个字无论如何都得改），
  R7 不行——「优化思路来自导师评审」里的优化只是叙述用词。R7 的告警是提问，不是判决。
- **区分「主张」和「被描述」。** `活动确为副部长牵头 → pass` 里的牵头在描述既成事实，
  不是在主张自己牵头。判据是词后是否紧跟分句终止符（，。；：、等）——紧跟就是分句收尾，
  不算主张。不加这条，每份交付包的审计节都会因为「由 XX 牵头」被判成缺范围。
- **只查简历条目，不查叙述文字。** 与 R4 同范围：交付包第 3 节的 STAR 是口播稿，
  「我优化了接口」正是准备念出来的话。代价同样要说清楚——**以句号结尾的条目逃过 R7**，
  所以中文条目按规范以「；」结尾，英文条目以「；」或不分号结尾。

R7 查不出来的两类，仍需人工：

- **提出（限真原创）**：要能答「与已有工作的区别」，这是证据问题不是词法问题。
  机械检查只能逼用户补一句区别说明，而那句话对不对只有 agent 追问得出来。
- **主导是否真实**：R7 只能确认「带了范围」，不能确认「那个范围里真的是你在主导」。
  范围给了但归属错了，要靠追问树（视角 B）戳穿。


## 视角 D：一致性

17. 简历、面试稿、GitHub/证据文件三处数字一致？
18. 同一项目在不同材料里口径一致（不一处 33.6% 一处 35%）？
19. 故事的"难点"与"角色"不矛盾（如称"独立完成"却写"团队解决"）？
20. 电梯稿、简历、STAR 三者互相能对上？

## 视角 E：数字可复算 + 隐私（可执行检查）

21. **数字逐个回溯**：交付稿中每个数字 → 素材清单证据指针 → 考古模式下实际打开文件定位确认（文件、列名/行号、口径三对上）。定位不到 → 降级为定性或删除，不允许保留"应该有"的数字。
22. **隐私扫描**：交付物中无 API 密钥、私有服务器路径、他人姓名/联系方式/成绩等敏感信息；证据指针路径已脱敏。
